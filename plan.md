# CareerInsight AI — Implementation Plan

## Product scope

Build a working, research-oriented career decision-support web app—not a static mockup. The first deliverable is a deployable, extensible web prototype with real account workflows, persistent profiles and roadmap progress, an editable interest assessment, consent-based resume extraction, a deterministic and explainable career-ranking service, skill-gap computation, evidence-grounded AI explanations/coaching where the platform LLM is available, and an honest research/evaluation area. Recommendations remain decision support, not employment promises. The same versioned REST API will be independent of the browser frontend so a future React Native client can reuse it.

## Implementation approach

- **Frontend:** React + TypeScript + Vite SPA in `frontend/`. Use a small, accessible component system with reusable forms, charts and layout components; call only relative `/api/...` endpoints. Vite serves port 3000 for Preview and proxies API requests to FastAPI in development.
- **Backend:** Python FastAPI application in `backend/`, with REST routers, Pydantic validation, account/session services, resume parsing, recommendation/scoring, roadmap, research and coach services separated by responsibility. Keep business logic out of React components. Expose OpenAPI documentation from FastAPI.
- **Serving:** One container/process topology for Preview and publication. In development, run Vite on the configured Preview port and FastAPI on an internal development port. For a production container, build the SPA and have FastAPI serve the compiled assets and `/api` on the platform's `PORT` (default 3000); provide an unauthenticated readiness endpoint. Keep browser-facing URLs relative and compatible with the cross-site Preview iframe.
- **Persistence:** SQLAlchemy models and explicit additive Alembic revisions, using the managed MySQL `DATABASE_URL` in Webdev and SQLite as an explicit local-only fallback. Revision `0001` is a frozen explicit schema snapshot for fresh migrations, revision `0002` changes experience-level nullability, and revision `0003` adds coach-resource metadata; later schema changes must use new additive revisions. The already-initialized Preview is versioned at the current migration head. Production must run migrations rather than depend on `create_all`. Seed extensible career/skill/learning-resource catalog data idempotently; never overwrite user data on restart. Scope all private records to the authenticated user. Store roadmap completion durably. Process uploaded resumes in memory, display detected fields, and persist extracted data only after explicit user acceptance.
- **Authentication:** Implement the requested email/password registration and login, secure password hashing, protected APIs, and revocable server-side sessions. Use secure, HttpOnly cookies with `SameSite=None; Secure` for public HTTPS Preview and an appropriate plain-HTTP local configuration; do not derive cookie security from internal proxy scheme or `NODE_ENV`. Await profile/dashboard hydration before rendering Profile Setup and keep loaded profile data synchronized with the editor. Password-reset delivery will use optional SMTP configuration: if no sender is configured, say reset delivery is unavailable rather than exposing reset tokens.
- **Recommendation engine:** Put initial configurable weights (skills 35%, interests 25%, projects 15%, education 10%, target goal 10%, experience 5%) in backend configuration/database-backed settings. Compute each career score from structured user and role evidence, return factor-level contributions, matched and missing skills, supporting projects, and data coverage. Do not label the weights as validated research. Skill gaps use role-specific required levels and transparent beginner/intermediate/advanced mappings. Education alignment compares stated education with each role's education field; career-goal matching requires an exact catalogue role or controlled alias rather than generic shared tokens. Interest assessment accepts only seeded choices and applies controlled role-specific mappings; project evidence matches exact catalogue skills/tools/industry tags or listed project-type phrases, and unmatched projects receive a neutral factor score rather than generic keyword credit. Missing experience is nullable, explicitly distinguished from self-reported Beginner, neutrally scored, and excluded from known-data coverage. Recommendations and dashboard values are computed from the current profile and career catalog, never hard-coded display results.
- **LLM/RAG:** The scoring engine selects and ranks careers before any LLM call. Use the project-provided Manus LLM API only from the server; give it structured evidence and explicitly prohibit inventing profile details, skills, interests, career requirements or links. Retrieve seeded role descriptions, skill levels, education guidance, industries, tools and example projects as prototype catalogue context, clearly qualified as non-authoritative. Deterministically retrieve learning links from `rag/learning_resources.json`; its provider/title/URL/summary entries and source-specific caveats were reviewed on 2026-10-07. Display links in personalized roadmaps and coach replies, and persist them with assistant history. Label generated prose “AI-generated explanation.” If the service is missing, times out or returns unusable output, show a clear deterministic evidence-based explanation instead of fabricating AI output. Do not claim LLM calls are active if service credentials are unavailable.
- **Resume handling:** Accept PDF and DOCX only, check content type, extension, file signature and size, parse with maintained Python libraries, and return a reviewable extraction draft including text excerpts only from identified experience sections. Allow the learner to edit or remove extracted fields; an omitted list field remains removed. Experience excerpts are unverified source text and never infer or change the user's self-reported experience level. Require session and CSRF checks on upload. Provide accept/edit/reject before saving. Do not persist the original document by default.
- **Research integrity:** Restrict the evaluation area to authorized researcher/admin accounts, and make frontend role checks match server authorization. Pydantic-validate bounded labeled cases, all four method prediction lists and optional measurements; accept only catalogue career slugs/names. Compute macro precision/recall/F1 and top-3 accuracy, plus satisfaction and explanation-usefulness averages only from supplied 1–5 measurements and response-time averages only from supplied measured milliseconds, with observed sample counts. Omitted measurements remain absent, never invented zeroes. Never treat generated/synthetic demo profiles as observed research results. The literature survey and catalogue provenance must cite verified dated academic or authoritative sources; make no unsupported novelty, quality or outcome claims.
- **Sample experience:** Provide a clearly identified sample-profile action after sign-in; it populates an editable profile for demonstration and runs the actual scoring code. Seed realistic role and skill catalog records, not fake precomputed recommendations.

## User journeys and page scope

1. **Public landing:** CareerInsight AI brand, Home/How It Works/Features/Research/About/Login navigation, “Get Started” CTA, “Make Better Career Decisions with Explainable AI” hero, supporting copy, Start Career Analysis / Explore How It Works actions, a restrained User Profile → AI Analysis → Career Recommendation → Skill Roadmap diagram and four steps: Build Your Profile; Tell Us Your Interests; AI Analyzes Your Profile; Receive Personalized Recommendations.
2. **Accounts:** Login, registration, forgot-password request and reset-password screens. Registration collects full name, email, password/confirmation, education, degree, branch and graduation year. Login directs incomplete users to setup and complete users to their dashboard.
3. **Profile and interests:** Editable personal/technical/soft-skill/experience/project/certification/goal profile; short multiple-select interest assessment covering preferred work, problems, technologies and projects. Distinguish confirmed user selections from AI-inferred interests and allow edits.
4. **Resume review:** PDF/DOCX upload; extract education, skills, projects, certifications and experience; review/edit/accept/reject before persistence.
5. **Decision support:** Dashboard driven by server results; top career and alternatives, factor breakdown, evidence, skill gaps, roadmap and next action; dedicated career analysis, recommendation explanation, skill-gap and progress-tracked roadmap views.
6. **Career coach:** Contextual chat with suggested prompts (“Explain my recommendation,” “Show my gaps,” “Create my learning plan,” “Suggest a project,” “Compare my top two careers”). Load and display the signed-in user's persisted chat history and saved source links, scope history operations to the owner, and confirm before the user clears saved history. Use only the signed-in user's profile, recent bounded conversation, computed recommendation evidence and curated role/resource records; never guarantee employment or make unsupported/discriminatory claims.
7. **Research and settings:** Authorized-only evaluation view and account/profile controls. Show the required ethical disclaimer: “Career recommendations are decision-support suggestions and should not be treated as guaranteed career outcomes.”

## Data model and API boundaries

Create normalized users, profiles, skills, user_skills, interests, user_interests, career_roles, career_skills, projects, resumes (metadata/extraction status; no raw file by default), recommendations/evidence, skill_gaps, roadmaps, roadmap_progress and chat_history records, with foreign keys, ownership checks, indexes and migration history. Add configurable scoring settings and evaluation-run/test-case records where needed. Publish the requested endpoints: `POST /auth/register`, `/auth/login`, `/auth/logout`; `GET/PUT /profile`; `POST/GET /interests`; `POST /resume/upload`; `POST /career/analyze`; `GET /career/recommendations`; `GET /career/{id}` and `/career/{id}/explanation`; `GET /skills/gaps`; `POST /roadmap/generate`; `PUT /roadmap/progress`; and `POST /ai/chat`. Include routes for reset-password and researcher evaluation where required by the UI. Apply input validation, authorization, upload size/type checks, CSRF to cookie-authenticated mutations, per-action rate limits and read-only semantics to GET routes. Protected career analysis creates or refreshes a profile-aware roadmap; dashboard GET only reads.

The initial editable career catalog contains Data Analyst, Data Scientist, Machine Learning Engineer, AI Engineer, Data Engineer, Software Developer, Full Stack Developer, Cybersecurity Analyst, Cloud Engineer and Business Analyst. Each entry includes a role description, required/preferred skills and importance, education, tools, typical projects and beginner/intermediate/advanced expectations. Keep role definitions data-driven so more can be added without frontend changes.

## Design system

- **Design movement:** Contemporary university research analytics / editorial SaaS: quiet, precise, evidence-forward and approachable rather than a generic AI marketing template.
- **Core principles:** Legible evidence before generated prose; restrained hierarchy; transparent, editable personalization; accessible, responsive controls.
- **Color philosophy:** Deep navy (#16324F) conveys institutional trust for navigation and primary actions; slate blue (#3E5C76) carries secondary structure; muted teal (#2A7F7F) marks positive analysis without looking promotional. Warm off-white (#F7F8FA) reduces glare; white cards and fine #E2E8F0 borders preserve clarity. Use #1F2937/#64748B text, #2E7D5B success, #B7791F warning and #B94A48 error. Avoid neon hues, bright purple and excessive gradients.
- **Layout paradigm:** A calm editorial landing page transitions into a persistent, compact application sidebar with broad, aligned content; on mobile it becomes a menu and content cards stack. Use asymmetric narrative flow on the landing page; the dashboard uses a compact KPI strip, one prominent recommendation/evidence panel and carefully aligned detail sections rather than a wall of equal cards.
- **Signature elements:** A small “evidence ledger” treatment pairing each recommendation factor with its supporting user-provided inputs; a thin muted-teal progression line linking profile → analysis → recommendation → roadmap; restrained skill-level bars with explicit labels.
- **Interaction philosophy:** Every score can be inspected; inferred values are editable and visibly marked; resume extraction pauses for review; saving progress gives clear feedback. Keyboard-accessible focus, labels, errors and confirmation states are required.
- **Animation:** Minimal, short opacity/position transitions for navigation and progress changes only; respect `prefers-reduced-motion`; no parallax, pulsing or attention-grabbing continuous movement.
- **Typography:** Inter for interface and data labels, with a restrained editorial serif fallback for select landing-page display headings only if it preserves legibility. H1 32–40 px; H2 24–30 px; H3 18–22 px; body 14–16 px; labels 12–13 px. Use semibold headings and regular body text.
- **Brand essence:** “Evidence-led career direction for students and early-career professionals.” Personality: measured, intelligent, supportive.
- **Brand voice:** Clear, specific and non-promissory. Example lines: “See what your profile supports—and what to strengthen next.” “Every recommendation comes with its evidence.”
- **Wordmark/logo:** A compact editorial wordmark with a simple branching-path glyph that resolves into a check/evidence marker, never a generic chatbot icon.
- **Signature brand color:** Muted teal #2A7F7F, reserved for confirmed progress, evidence accents and the roadmap connector.
